# V0_IMPLEMENTATION_PLAN.md — План реализации вертикального среза

> Версия: 1.1 · 2026-11-19 · Статус: **план после утверждения решений V0**
> Очередь исполнения: задачи `T-010`…`T-050` в [`TASK_QUEUE.md`](TASK_QUEUE.md). Текущий фокус: [`STATUS.md`](STATUS.md).
> Не является готовым игровым прототипом. Не запускает массовую генерацию ассетов и не открывает главы 02–12.

## 0. Цель V0

Собрать **один проверяемый вертикальный срез** стиля Premium Clean Stylized Fantasy 2.5D для Android 9:16:

| # | Элемент | ID |
|---|---|---|
| 0 | Заставка с названием | `UI-SPLASH-V0` |
| 1 | Главный экран | `UI-HOME-V0` |
| 2 | Локация Уфы | `L01` |
| 3 | Боевая арена | `ARENA-L01` |
| 4–6 | Герои | `H01` Каэрон, `H02` Вейриса, `H03` Эльдарион |
| 7 | Противник | `E01` Живой талон |
| 8 | Текстовый диалог + статичные портреты | `UI-DIALOG` / CH01-Q01 |

## 1. Утверждённые решения (входные)

1. Название **«БашЛегенды: Эпоха Абсурда»** на splash и home; repo `SarcasmAfk` и package ID без rename.
2. Диалоги: **статичные портреты**; без lipsync и сложной лицевой анимации.
3. Бой: **Blender 3D → анимация → прозрачные 2D-атласы → Godot 4**.
4. Приоритет: оптимизация Android, 9:16, единый стиль.

## 2. Запреты этого этапа

- Массовая генерация ассетов вне списка V0.
- Разработка глав 02–12 и локаций L02–L11 (кроме упоминания тизера при необходимости в тексте).
- Объявление документации «готовым прототипом».
- Переименование репозитория / applicationId.
- Тяжёлый 3D runtime персонажей на устройстве.

## 3. Фазы реализации

### Фаза V0-A — Спека и каркас клиента (документы + скелет Godot)

**Выход:** пустой Godot 4 проект 9:16, навигация Splash → Home → (заглушки) Location / Battle / Dialog; моки данных; **без** финального арта.

Задачи:
1. Создать Godot 4 проект (имя продукта display = рабочее название; package позже отдельно).
2. Экраны-заглушки по DESIGN_SYSTEM ID.
3. Подключить цветовую тему (токены).
4. Загрузить текст CH01-Q01 в Data-ресурс (мок).
5. Чеклист: запуск на desktop export / Android debug при наличии SDK.

**Приёмка:** сцены открываются, ориентация портрет, название видно на splash/home (даже временным шрифтом).

### Фаза V0-B — Точечный арт только для среза (не массово)

**Выход:** ограниченный набор draft-ассетов V0; каждый с статусом `draft`/`review`.

Порядок производства:
1. Wordmark + splash/home BG (paintover).
2. L01 слои + ARENA-L01 floor/BG.
3. Концепты H01–H03 + E01 → UI/dialog portraits (static).
4. Blender blockout H01 → bake idle/attack test atlas (пилот пайплайна).
5. Затем H02, H03, E01 по тому же пайплайну.
6. UI: primary/secondary buttons, dialog panel, 8–16 иконок минимума.

**Приёмка:** силуэт-тест; палитра; прозрачность атласов; бюджет Low-пресета описан; **нет** утверждения «финальный арт всей игры».

### Фаза V0-C — Сборка среза в Godot

**Выход:** проходимый demo-path: Splash → Home → L01 → Dialog Q01 → Battle vs E01 (автобой-заглушка допустима) → назад на Home.

Задачи:
1. Параллакс L01 (3–6 слоёв по пресету).
2. Dialog с портретами speaker_id → texture.
3. Battle layout 2 линии; 3 героя + E01 на атласах.
4. Пресет Low отключает particles.
5. Профилирование памяти на устройстве ≥6 ГБ (если доступно) или оценка размера текстур.

**Приёмка:** путь проходим; 9:16; нет крашей; документация обновлена фактом (что сделано / что placeholder).

### Фаза V0-D — Review и стоп-линия

1. Визуальный review владельцем.
2. Список дефектов / правок только по V0.
3. Решение: расширять CH01 арт **или** сначала Phase 0 API/инженерия по ROAD.
4. Явно **не** стартовать главы 02–12.

| Категория | Макс. единиц в V0 |

## 7. Риски

| Риск | Митигация |
|---|---|
| Bake-атласы раздувают память | Лимит 2048², меньше кадров на Low |
| Blender-пайплайн дольше чистого 2D | Пилот только H01 до масштабирования |
| Нет CI в репозитории | Добавить минимальный docs/lint workflow отдельно (не блокер документов) |
| Контент HEROES/CAMPAIGN ещё «проектный» | V0 использует H01–H03/L01 как утверждённый срез стиля, не как финальный лор-лок всей кампании |
