## 1. Неизменяемые решения о процессе

- **ROAD-001 C:** расширенный MVP (12 героев, несколько городов, гильдии, арена, события; также кампания и AFK).
- **ROAD-002 A:** сначала весь клиент, потом сервер. До создания клиентских экранов согласовать API-контракты и структуры данных; моки явно маркировать.
- **ROAD-003 D (пользовательский вариант):** тесты + аудит + своевременное обновление дорожной карты.
- **Запрет:** не начинать полноценную реализацию модуля без утверждённой детальной спецификации.
- **Запрет:** не помечать функциональность готовой на основании наличия кода без проверок.

## 7. Правила своевременного обновления

1. Перед началом задачи: сверить GDD и ROAD, указать точный статус и цель.
2. Перед кодом: оформить и утвердить подробное ТЗ этапа, зависимости и критерии приёмки.
3. После каждого значимого изменения: обновить прогресс и ссылки на коммиты.
4. После тестов и аудита: записать результаты, дефекты и решение о готовности.
5. При изменении объёма работ: явно отметить отклонение и получить согласование.
6. При передаче работы другому ИИ: сначала `AGENTS.md` → `STATUS.md` → `TASK_QUEUE.md` → `DECISIONS.md` → `INDEX.md`, затем GDD/ROAD и **проверка фактического кода/ассетов**.
7. Не заменять выбранные пользователем варианты «более удобными» без нового утверждения.
8. Не плодить новые «источники истины» статуса: NOW только в `STATUS.md`, очередь только в `TASK_QUEUE.md`, решения только в `DECISIONS.md`.
